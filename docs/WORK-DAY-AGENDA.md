# Work Day workspace and calendar

Tasks uses the wider column and grows to at least 700px of scrollable rows on desktop (78% of viewport height on larger screens). Project grouping, ordering, completion, and load-more remain available. Calendar, Reminders, and Waiting on occupy the adjacent column. Up to ten active reminders and ten dependencies appear before links to their complete lists. Focus and the brief remain below Tasks. Projects and Learning remain in navigation and no longer add dashboard queries.

The calendar uses the existing owner-bound Microsoft connection and read permissions. Today and Next 7 days use America/New_York midnight boundaries, including DST. The authenticated `/api/microsoft/calendar` endpoint returns only event IDs, names, times, all-day status, duration, retrieval time, and truncation status. Cancelled and declined events are excluded. Recurring occurrences come from Microsoft's calendarView endpoint. It reuses the existing bounded reader (up to 75 entries); truncation is disclosed rather than presented as a complete calendar. Microsoft reference: https://learn.microsoft.com/en-us/graph/api/user-list-calendarview?view=graph-rest-1.0

The calendar loads independently and refreshes every five minutes while visible, when returning to the app, or on manual Refresh. Responses use no-store; the PWA bypasses API and authorized requests. No calendar content is stored in the database or offline cache. Calendar outages leave the rest of the workspace usable. Both website and PWA use this same responsive layout.

Verification covers the authenticated minimal response, owner isolation, revoked membership, invalid ranges, DST, event duration, all-day display, outage isolation, accessibility, desktop/mobile layouts, and PWA static-only caching and update behavior. Rollback is the application commit; there is no database migration or new permission grant.
